THE METHOD

Measure what makes a study informative.

Study capacity is the main benchmark. Treatment benefit and demonstrated model performance are separate questions.

Begin with the biological record.

Who was measured? What was collected? How often? Which observations belong to the same person and time? These questions establish the record that future models can learn from.

Make information claims explicit.

A thousand correlated measurements are not a thousand independent directions. Information estimates depend on the biological target, observation operator, noise, and experimental design.

SIX COMPLEMENTARY FAMILIES

A profile of strengths.

01Biological depth
What can one linked measurement event resolve?Intensive capacity · independent directions and information within an event
02Population information
How much information does the retained population contribute?Extensive capacity · population support on a declared target space
03Time & trajectories
Which changes and timescales can repeated observations distinguish?Longitudinal capacity · temporal support, span, and repeated observations
04Perturbation & causality
Which intervention contrasts can the design identify?Causal capacity · assignment, controls, and linked response windows
05Personalized learning
Can responses be distinguished across people, contexts, and sequences?Personalized and sequential capacity · modifiers and decision histories
06Transfer across contexts
Where does the design support learning beyond one setting?Transport capacity · overlap and support across declared contexts

How a comparison earns its claim

Name the metric, preserve its units and denominator, and bind it to the source and implementation version. Compare information estimates only on the same biological target and model basis. Leave unavailable quantities unresolved.

Reported literature facts are useful even when a complete information model is unavailable. Their definitions stay visible in the study table.

An open-ended benchmark

Native measures can keep growing with deeper observations, longer follow-up, stronger experiments, and broader populations. There is no universal “100% of human biology.” New benchmark levels need explicit tasks and validation criteria.

Treatment outcomes and held-out AI performance can accompany a study profile. They do not determine the core collection or design score.

RUN ANIBENCH

Your data. The same open benchmark.

Run locally, inspect the code, and keep participant records private.

01 / INSTALL

Start with the source package.

Use Python 3.10 or newer in a virtual environment.

git clone https://github.com/anibiome/anibench-benchmark.git
cd anibench-benchmark
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
Windows activation

In PowerShell, use .venv\Scripts\Activate.ps1 instead of the source line.

02 / PROFILE THE COLLECTION

See what the record contains.

Run the included synthetic CSV example, then map your own local tables. The mapping names the roster, target columns, event times, and QC rules. 

anibench profile-tables examples/collection/table-map.json \
  --out build/collection.json --pretty

03 / EVALUATE THE DESIGN

Inspect all six capacity families.

Start with a declared geometry example. To evaluate your study, supply its retained or planned observations, assignment structure, and explicit information-model assumptions. 

anibench eval web/protocol-capacity-example.json \
  --out build/design.json --pretty

For a local interface, run anibench studio and open http://127.0.0.1:8765/explore.html.

Geometry and comparison guide ↗

04 / COMPARE & CONTRIBUTE

Make the result reproducible.

Compare one collection metric with explicit units, denominators, and missing-data bounds. Each category has its own result; no weighted total decides an overall winner. 

anibench compare-records study-a.json study-b.json \
  --basis comparison-basis.json \
  --out comparison.json --pretty

Metric cards and comparison rules ↗

For model-based geometry, anibench compare computes within-family Pareto relations from compatible evaluation receipts.

For a public contribution, submit the protocol, source references, definitions, and reviewed aggregate receipt. Keep participant records and clinical values in your governed workspace.
